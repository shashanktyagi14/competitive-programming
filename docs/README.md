# Repository Guide

The repository is currently Codeforces-focused. The root [README](../README.md) is generated by CFPusher and remains the canonical topic-wise listing. Avoid hand-editing its generated tables; changes can be overwritten the next time the index is refreshed. The contest index groups those same submissions by round.

## Organization conventions

- **Platform:** keep Codeforces submissions in the current CFPusher-managed root. When adding another platform, place it under `platforms/<platform>/` rather than mixing contest identifiers.
- **Contest:** use `<contest>/<task letter> - <problem title>/solution.cpp` for existing Codeforces submissions.
- **Topic:** use the tags in the root CFPusher README for cross-contest discovery; add deeper human-written reasoning to `SOLUTIONS.md`.
- **Practice:** use `practice/<topic>/<problem-slug>/` for problems without a verified platform/contest submission.

## Layout

- `<contest>/<letter> - <problem title>/solution.cpp`: original contest submission.
- The matching README.md in a problem directory: statement metadata and submission details supplied by CFPusher.
- [Selected solution notes](SOLUTIONS.md): human-written reasoning and complexity analysis.
- [Contest-wise index](INDEX.md): generated cross-reference by contest and topic.
- [Practice solutions](../practice/): solutions for exercises whose source platform is not specified.
- [Sample test runner](../tools/run_samples.py): compiles selected C++ files and checks regression samples.

## Updating the index

From the repository root, run:

```bash
python tools/generate_index.py
```

The script reads the topic tables in the root README and regenerates docs/INDEX.md.

## Running regression samples

Install a C++17 compiler such as GCC, then run:

```bash
python tools/run_samples.py
```

Set the CXX environment variable to use another compiler command. Test cases and expected outputs live in tests/manifest.json.

## Adding a solution

Keep the original contest/platform path intact, use the problem's official identifier in the folder name, and add a focused explanation where the approach is non-obvious. Include small reproducible tests for tricky boundary cases. Do not label a practice exercise as an accepted contest submission unless it has actually been submitted and accepted.
